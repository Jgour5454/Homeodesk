# HomeoDesk

HomeoDesk is a React frontend plus an Express/Mongoose backend for a homeopathy clinic portal.

## Architecture

- React frontend in `src/`
- Express API in `server/`
- MongoDB Atlas is the runtime database for users, doctors, appointments, consultations, clinical records, diet plans, feedback, and password-reset state
- JWT authentication with role-based doctor/patient authorization
- No JSON files are read by the application at runtime

## Setup

### Backend

```bash
cd server
npm install
cp .env.example .env
```

Fill in a real MongoDB Atlas URI and strong secrets in `server/.env`, then:

```bash
npm run seed:doctor
npm start
```

### Frontend

From the project root:

```bash
npm install
npm start
```

For local development the frontend defaults to `http://localhost:5000/api`. For production, set `REACT_APP_API_URL` to the deployed API URL before building.

## Existing legacy data

The archive includes the previous JSON data under `server/migrations/legacy-data/` only for one-time migration. The running application never reads those files.

After configuring MongoDB, run:

```bash
cd server
npm run migrate:legacy
```

The migration maps old numeric/string user IDs to MongoDB ObjectIds and preserves relationships between patients, doctors, appointments, consultations, records, diet plans, and feedback.

## MongoDB URI

Use the exact connection string generated by MongoDB Atlas. If the username or password contains URI-reserved characters, URL-encode them. Do not commit `.env` or real credentials.

## Security

The corrected archive intentionally does not contain the previous live MongoDB password or JWT secret. Rotate those credentials in MongoDB Atlas and your deployment environment before going live.
